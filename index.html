01

MediSA

Medical Triage & Doctor Recommendation

Most patients in Bangladesh describe symptoms in plain language to a general doctor who then decides if a specialist is needed: a process that is slow, inconsistent, and often wrong. MediSA replicates that triage logic in software: Collects symptoms through dynamic interactive conversations, runs it through a RAG pipeline backed by FAISS vector search, predicts the likely condition, and routes the patient to the right specialist category.

I chose RAG over a fine-tuned model because the medical knowledge base needed to stay updatable without retraining. FAISS handles the vector retrieval locally, keeping the system self-contained and fast. MediSA also generates a structured medical summary the doctor can actually use before the appointment. Recognized as a National Finalist at MillionX AI Buildathon, selected from 400+ teams.

02

Incident Ops System

AI Incident Management Platform / Active development

On-call teams waste time manually reading alerts, deciding severity, and figuring out who owns the problem; meanwhile the SLA clock is running. Incident Ops automates the first response: incoming incidents get semantically classified, prioritized by severity, and routed to the right team based on role.

I used Celery with Redis as the task queue rather than handling async work in FastAPI directly, because SLA timers need to keep running even if the API restarts. That separation of concerns matters in a system where missing a deadline has consequences. RBAC ensures the right people see the right things. Every action is logged for audit.

03

SmartPark AI

Multi-Agent Parking Management

Drivers circle looking for parking while half the spots in a lot sit empty because there is no system connecting supply to demand in real time. SmartPark closes that gap using a multi-agent architecture where each agent has one job: one monitors and predicts occupancy using ML forecasting, another handles automatic slot assignment, and a third sends drivers real-time notifications.

I split the work across agents rather than one monolithic service because each concern scales and fails independently. If notifications go down, parking assignment keeps working. Operators get a live map and full activity log. Deployed publicly on Vercel.

04

PredictWise

Multi-Model ML Prediction API

Most ML demos tie the model directly to the serving layer: swap the model and you are rewriting the API. PredictWise separates those concerns: different Scikit-learn models plug into the same FastAPI serving layer without touching the API contract.

I trained multiple model(.pkl) and added them in a existing system using FastAPI, the goal was to learn how to connect .pkl model in real world system not gaining 100% accuracy. Smaller project in scope: the focus here was getting the architecture right, not the model count.

05

UniMind

AI Academic Intelligence System / Active development

Universities usually find out a student is struggling when they fail an exam; by then the semester is mostly gone. UniMind surfaces that risk weeks earlier: ML models trained on academic patterns flag at-risk students before the failure happens, and an LLM-powered assistant helps academic staff understand what the data is saying and what actions to take.

I split the backend across FastAPI and Django by concern: FastAPI handles the ML inference and prediction endpoints where speed matters, Django manages the admin workflows and data models where structure and built-in tooling matter more. Currently in active development.
